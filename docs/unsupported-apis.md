# PR 2023 上已证实不可用的 API

**别再试了。** 下面这些在 Premiere Pro 2023 (23.2.0) 的脚本调用下走不通，
本页记录现象与替代方案，节省你重复踩坑的时间。

---

## `attachProxy(path, isHiRes)` —— 恒返回 false

**试过的组合（全部失败）**
- 正斜杠路径 / 反斜杠路径
- 中文路径 / 纯 ASCII 路径
- 0 / 1 作为第二参数

**现象**
始终返回 `false`，代理挂不上，也不抛异常 —— 静默失败。

---

## `changeMediaPath(path, ...)` —— 触发模态框，且换不成功

**现象**
调用后 Premiere 触发 importer 同步导入，弹出
「导入程序报告了一个一般错误」模态框，**把主线程卡住**。
模态框出现后，所有 `evalScript` 都会超时（见 troubleshooting）。

**结果**
路径没有换成功，还赔上一次主线程阻塞。

---

## 代理工作流的替代做法（本项目采用）

放弃「导入原片再挂代理」的思路，改为：

1. **直接 `importFiles` 导入代理 MP4**，用它铺设时间线（快，剪辑流畅）
2. 脚本自动生成一份 **`代理原片对照表.json`**（代理路径 -> 原片路径）
3. **导出前**用「链接媒体」按对照表把代理替换为原片，或在 PR 里手动重链接

这样绕开了两个不可用的 API，同时保留了标准代理流程的收益。

---

## 其它实测注意点

| 项 | 说明 |
|---|---|
| `importFiles` 的布尔参数 | 必须是 `True`/`False`，传 `1`/`0` 行为不一致 |
| `clips[i].remove()` | **必须传 2 个参数**（只传 1 个会报错） |
| 一次导入过多素材 | PR 2023 会卡 UI；本项目默认每批 8 条 |
| 导入大文件后整体变慢 | PR 在生成峰值文件与做音频一致性分析，属正常现象，等待即可 |
| 序列预设 | 只支持 GUID，不支持 `.sqpreset` 路径（见 pitfalls 坑 9） |

## 如何自己验证某个 API

本仓库提供 `scripts/pr_probe_api.py`，可在真实 PR 里逐个试 API 并打印结果。
新增不可用条目时，请一并记录：**试了什么参数组合、返回什么、有没有弹框**。
